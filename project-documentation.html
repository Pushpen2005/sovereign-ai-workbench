1. Executive Overview & Problem Statement

SovereignAI Workbench is a 100% local-first, air-gapped compliance intelligence and data execution platform designed for industrial operators, defense facilities, and compliance auditors who handle confidential SOPs, blueprints, and machinery sensor data.

💡 Core Value Proposition
Eliminates third-party cloud data transmission, token cost unpredictability, and internet latency dependencies by running hardware-accelerated local LLMs (Apple Silicon MLX / Ollama), local vector retrieval (Qdrant), local FastEmbed ONNX embeddings, and isolated Docker code sandboxes entirely on on-premise hardware.

Target Personas

  • Industrial Plant Engineers: Upload machinery SOPs and operational logs to identify equipment risks.
  • Compliance Auditors: Audit plant facilities against regulatory guidelines and export downloadable DOCX approval reports.
  • Data Analysts: Execute Python data analysis against industrial CSV datasets inside a network-isolated Docker sandbox.

The frontend is a modular React SPA built with Vite. State management relies on React Context API divided cleanly by domain:

10. Authentication & Security Boundaries

🛡️ Security Enforcement Summary
  • Password Hashing: Bcrypt with cost factor 10.
  • JWT Signing: HMAC SHA-256 tokens carrying userId and organizationId claims.
  • SQL Injection Guard: 100% parameterized SQL prepared statements in repositories.
  • Sandbox Isolation: Docker containers with NetworkMode: 'none', read-only root FS, 512MB RAM, 30s timeout.

11. AI / RAG Pipeline Deep Dive

The RAG engine follows a multi-stage pipeline:

  1. PDF Extraction: pdf-parse extracts raw text streams; OCR processes scanned document pages.
  2. Sliding Window Chunking: 1000 character size with 200 character overlap preserves sentence context boundaries.
  3. FastEmbed Embedding: BAAI/bge-small-en-v1.5 generates 384-dimensional dense vectors locally.
  4. Qdrant Vector Retrieval: Cosine similarity search filters candidate vectors by mandatory organizationId payload.
  5. LLM Inference: Formatted prompt with top-K context chunks is sent to Gemma-2-2B MLX for zero-shot JSON finding extraction.

12. Docker Sandbox Security Architecture

Python execution in the Coding Sandbox is managed by sandbox.service.js using Dockerode:

Container Options:
- Image: python:3.11-slim
- HostConfig.NetworkMode: "none" (Zero outbound network access)
- HostConfig.Memory: 536870912 (512MB RAM limit)
- HostConfig.NanoCpus: 1000000000 (1.0 CPU limit)
- Read-only Root Filesystem with tmpfs output mount

13. Real-Time SSE Architecture

Long-running inspection jobs publish step updates through execution-events.service.js, writing SSE frames (text/event-stream) to active browser connections without HTTP timeout risks.

21. Project Terminology Glossary

  • Air-Gapped: Operating with zero outbound or inbound external internet connectivity.
  • RAG (Retrieval-Augmented Generation): Injecting retrieved vector search text chunks into LLM context prompts.
  • Cosine Similarity: Normalized vector distance metric measuring semantic orientation similarity.
  • Server-Sent Events (SSE): Lightweight unidirectional HTTP streaming protocol for real-time browser progress events.

Category: B. Architecture

Question 6 — Microservices vs Monolith Design Decision
Medium Critical
"Judge may ask: Why did you choose a decoupled microservice architecture separating the API Backend from the AI Service?"
💡 Strong Answer (Say this to the Judge)
Document extraction, OCR, vector embedding calculation, and LLM inference have vastly different memory, hardware, and lifecycle characteristics compared to Express web route handling. Separating the AI Service (`ai-service` on port 5001) from the Node.js API Gateway Backend (`backend` on port 9000) prevents long-running PyTorch/ONNX memory allocations from blocking I/O bound web server events and enables independent scaling of compute components.
🔍 Code Evidence
docker-compose.yml backend/src/services/inspection-orchestrator.service.js ai-service/inspection/inspection.service.js
🧠 What You Should Understand
Web gateways are I/O bound and require fast event loop iteration, whereas AI services are CPU/GPU bound. Coupling them into a single process leads to node event loop starvation during vector generation or OCR.
🔮 Follow-up Question Judge May Ask
"How do the backend and AI service communicate?"
✅ Follow-up Answer
They communicate via HTTP REST endpoints over Docker's internal bridge network (`http://ai-service:5001`), authenticated via organization context headers.
Question 7 — Inter-Service Resilience & Circuit Breaking
Hard High ⚠️ Judge Trap

Question 8 — Worker Task Isolation & Sandbox Execution
Hard Critical ⚠️ Judge Trap
"Judge may ask: How do you prevent untrusted Python code executed in the Coding Sandbox from crashing the main Node.js process?"
💡 Strong Answer (Say this to the Judge)
Code execution is completely decoupled from the main Node.js runtime. `sandbox.service.js` uses the Dockerode SDK to dynamically create an ephemeral Docker container using `python:3.11-slim`. The code runs inside an isolated container with `NetworkMode: 'none'`, 512MB RAM cap, 1.0 CPU quota, 30s hard timeout, and read-only filesystem bindings except for a temporary output directory.

backend/src/services/sandbox.service.js backend/src/services/agentTools/sandboxCode.tool.js Dockerfile

✅ Follow-up Answer
The Docker container execution is subject to a 30-second timer; upon timeout, `sandbox.service.js` forcefully issues container `kill()` and `remove()`, returning a structured timeout exit code.
